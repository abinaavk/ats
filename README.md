# ATS

Root-only service manager for Python/Flask, Node and optional Docker services,
with systemd, Cloudflare tunnel routes, signed GitHub webhooks and backups.

Run `sudo python3 app.py` interactively once to configure the instance. Preserve
its configuration and database when upgrading. Run `sudo python3 app.py --daemon`
as your existing ATS daemon service for the scheduler and webhook listener.
Restart that daemon after upgrading; headless requests do not start a listener.

## Monitor integration

The monitor's Manage tab invokes the same ATS operations using JSON on stdin:

```sh
printf '{}' | sudo python3 app.py --api services.list
printf '{"name":"example","action":"restart"}' | sudo python3 app.py --api services.action
```

Stdout is NDJSON: optional `log` and `step` events, then exactly one `result`
with `ok` and either `data` or `code`/`error`. Exit status is zero on success.
Missing instance configuration fails with `not_configured`, without a wizard or
CLI lock. `ATS_CONFIG_FILE` and `ATS_INSTANCE` select the existing instance.

Operations cover `settings.get/set`, `services.list/get/deploy/redeploy/delete`,
`services.action`, `services.config.set`, `services.logs/clear`, status/resources,
`backups.list/create/restore/delete`, `webhook.get/set/test`, dependencies, port
suggestions, domain checks, Docker availability and Cloudflare status/sync/restart.
Arguments and validation are implemented in `ats_api.py` and
`ats_manage_runtime.py`; the interactive app and signed webhooks share the update
path. Updates fast-forward the configured branch, install changed dependencies,
rebuild Docker images, restart and check health. Branch changes check out the new
branch; preserve any local changes before an update.

Use the matching `ats-monitor` Manage change. Configure its `ATS_CLI` to a
root-owned launcher for this instance and set up narrowly scoped sudo access if
needed. Keep the launcher, ATS code and their parent directories unwritable by
the monitor service account. See the monitor's `docs/manage.md` for deployment.

For Global management on port 9997, install the companion Monitor adapter and
preview its complete service environment with `server adapter`. See
[Global Monitor adapter setup](docs/global-monitor-adapter.md) and
[persistent startup](docs/persistent-startup.md). A passing signed health check
does not verify management reads or writes.

## Upgrade notes

- Existing unsigned GitHub webhooks need the per-service secret shown in Manage
  or the ATS webhook menu. Use JSON, push events and SSL verification. The
  listener binds to `127.0.0.1`; the local tunnel exposes it publicly.
- Docker is optional. It requires a root Dockerfile and socket access for the
  configured service user. Compose is unsupported. Systemd runs the foreground
  container; its CPU/memory limits and port forwarding are generated by ATS.
- Storage settings affect future deployments. Existing service and local backup
  paths are retained. Backups cover the service database directory; Docker mounts
  that directory at `/data`. Keep encryption keys with your recovery material.
- Cloudflare sync repairs current service routes and preserves unrelated routes
  and catch-all rules. Unowned routes require manual review rather than automatic
  deletion.

## Tests

Requires PyYAML; the cross-repository bridge check also needs Flask and a sibling
`ats-monitor` checkout. Run from this directory:

```sh
python3 -m unittest discover -s tests -v
```

Host integration tests use temporary config, database and unit directories plus
fake Git, Docker, systemctl, OpenSSL and rclone commands. They do not verify a real
Docker daemon, systemd host, Cloudflare tunnel, Google Drive or GitHub delivery.
Use a disposable service for the final server check after an approved merge.
